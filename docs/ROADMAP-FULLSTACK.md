# 全栈化路线图 v2：以「AI 能力」为主线，平台工程只当骨架

> 本文是 `react-local-rag`（浏览器端离线 RAG）升级为全栈产品的规划与任务清单。
> 每完成一项就把 `[ ]` 改成 `[x]`；每阶段末尾有验收标准。
>
> **v2 相对 v1 的核心变化**：砍掉平台运维类条目（多租户体系、Celery 队列、OCR、Grafana/SLO/成本分摊），
> 把省下的时间投到 AI 能力主线。原则是——**每个待办都必须能回答"它证明了什么 AI 能力或工程判断"**，
> 答不上来的就属于运维，进「非目标」。
>
> 注意区分：砍的是**框架与运维面**，保留的是**机制**。例如 Celery 砍掉，但"异步摄取 + 断点续跑 + 增量重建"
> 保留（用 LangGraph 图编排 + 任务状态表实现）；Grafana 砍掉，但"单请求成本/延迟可归因"保留（Harness 的预算门槛依赖它）。

---

## 0. 定位（决定取舍）

**一句话**：在浏览器内、无网络、约 1GB 内存预算下，做出**引用可回跳、无依据会拒答、每次改动都有回归门槛**的文档问答引擎；并给出它在什么规模下该让位给服务端。

**主 ICP**：需要「知识问答但数据不能出域、答案必须能追溯」的组织内知识密集团队。
**主场景（P0）**：制造业/能源内网 SOP 与设备手册问答。
**不适用场景**（写进 README，用来证明你知道边界）：C 端通用问答、通用 LLM 网关、跨模态检索、面向个人开发者的玩具型 demo。

**差异化四件资产**（开源平台普遍缺失）：

1. **可追溯引用 + 拒答判定**：回答逐句带角标 → 引用卡片 → 原文回跳；无依据必须拒答
2. **评测驱动**：golden set + 负样本 + 固化向量 + CI 门槛，任何改动都有前后对比数字
3. **离线 / 隐私双模**：浏览器本地模式（无网可用）+ 服务端模式
4. **结构化分块 + 索引版本**：跨块问答、索引过期可感知、可灰度重建

## 1. 能力主线（把清单从"功能"改成"证据链"）

每条任务只属于以下四类能力之一，标注在各阶段标题上：

| 能力类型 | 含义 | 面试价值 |
| --- | --- | --- |
| **[可靠]** | 让弱模型/受限环境下的输出可信（引用、拒答、一致性） | 最高：证明你在"效果不够好"时靠工程补 |
| **[可验]** | 让每次改动可量化验证（Harness、指标、回放、影子评测） | 最高：绝大多数项目没有 |
| **[约束]** | 资源/网络/隐私约束下的系统设计（离线、内存、单线程） | 高：真实一线经验 |
| **[对外]** | 把能力开放出去（MCP、Skills、双端对比） | 中高：体现抽象与产品判断 |

## 2. 目标架构

```
L1 客户端   Web 前端(引用卡片/HITL)  |  浏览器本地引擎(Lite 隐私模式)  |  CLI/SDK
L2 接入     API 网关(FastAPI)  |  认证 + 单租户（多租户属非目标）  |  请求配额（仅日志级）
L3 编排     LangGraph 状态机(checkpoint/interrupt/stream)  |  Skills 注册表  |  MCP Client/Server  |  HITL
L4 检索     Query 改写/分解  |  混合检索(BM25+向量)  |  Rerank  |  ACL 过滤  |  索引版本
L5 摄取     解析(PDF/DOCX/MD/TXT)  |  结构化分块  |  Embedding  |  增量索引（进程内任务）
L6 数据     Postgres + pgvector（单库起步）  |  本地磁盘存原文（MinIO 按需再引）
L7 Harness  数据集版本化 | 指标服务 | 门槛+预算 CI | 轨迹回放 | 故障注入 | 影子评测 | 标注台
横向         可观测 = OTel trace + 成本/延迟归因（不做 Grafana/SLO）  |  模型双通道(Ollama/vLLM + 云端)
```

### 选型与理由

| 层 | 选型 | 理由 | 明确不选 |
| --- | --- | --- | --- |
| 后端语言 | **Python 3.12 + FastAPI** | LangChain/LangGraph 生态在 Python | 不用 Node 重写编排 |
| 编排 | **LangGraph** | checkpoint/回放/HITL/流式，Harness 的轨迹回放直接依赖它 | 不手写 agent 循环 |
| 元数据+向量 | **Postgres 16 + pgvector** | 一个库起步、事务一致、少一个运维对象 | 初期不上独立向量库 |
| 关键词 | **pg_trgm/pg_jieba FTS** 起步，规模到了再换 OpenSearch | 中文需分词；BM25 精确匹配型号/数字是刚需 | 不在 SQL 里 `LIKE` 拼检索 |
| 文件存储 | **本地磁盘**（挂载卷），MinIO 按需 | 私有化单机部署最简单 | 不用数据库大字段存文件 |
| 异步任务 | **进程内任务 + 任务状态表**（M2/M3 用 LangGraph Ingestion Graph 编排） | "异步 + 断点续跑"是机制；"用哪个队列框架"不是亮点 | **不引 Celery/ARQ/Redis 布队** |
| 模型 | **LiteLLM 统一**：本地 Ollama/vLLM/BGE + 云端 OpenAI 兼容 | 一套接口双通道，合规场景切本地 | 不把 provider 硬编码进业务 |
| 前端 | 复用现有 React + 新增"服务器模式"开关 | 引用卡片/步骤面板/perf 面板是资产 | 不重写前端 |
| 部署 | **Docker Compose**（api + postgres） | 私有化交付首选 | 第一天不上 K8s |
| 观测 | **OTel trace + 成本/延迟归因** | 让每个请求可解释，喂给 Harness 预算门槛 | **不做 Grafana/SLO/成本分摊** |
| 权限 | **ACL 检索过滤**（唯一保留的"平台"能力） | 后过滤会污染召回，是检索层难点 | 不做多租户/RBAC 矩阵/审计台 |

## 3. 从现有项目继承什么（不要丢资产）

- **分块器 + ChunkMeta schema** → 抽成《跨语言分块规范》，Python 端重写后用**同一份 corpus** 验证切块一致（contentHash 对齐）
- **评测体系**（golden/负样本/门槛/固化向量）→ 演化为 Harness，这是最难被抄的资产
- **引用装配 + 拒答判定** → 写成 API 契约（citations / verdict / evidence_snapshot）
- **indexVersion + 索引过期提示** → 后端索引版本表 + 重建任务 + 灰度
- **降级路径设计**（向量不可用→BM25-only；云端失败→本地）→ 扩展成故障注入矩阵
- **前端 UI** → 引用卡片、Agent 步骤面板、性能面板直接复用
- **不再复用**：推理锁、单线程 WASM hack、IndexedDB 存储层（换服务端存储）

## 4. Harness Engineering（最稀缺的一段）

> 定义：让**模型、提示词、检索参数、Agent 轨迹**的每一次改动，都能被自动验证的工程基础设施。

| # | 组件 | 具体做什么 | 为什么值钱 |
| --- | --- | --- | --- |
| H1 | 数据集工程 | golden set 版本化；失败案例自动回流；合成数据 + 人工抽检 | "回归集会腐烂"，需要治理流程 |
| H2 | 指标服务 | 检索(recall@k/MRR/NDCG)、生成(引用精度/引用召回/拒答正确率)、系统(p50/p95/成本)、Agent(工具成功率/步数/无进展率) | 多口径并存且要可解释 |
| H3 | 门槛与预算 CI | 分模式门槛 + **延迟/成本预算**（超标即失败） | 拦住"更准但慢 10 倍"的改动 |
| H4 | 轨迹回放 | LangGraph 每次运行落库(state/tool calls/outputs)，离线重放**不重新调模型** | 定位"从哪一步开始错"的唯一高效手段 |
| H5 | 故障注入 | 模型超时/乱格式/检索空/429/权限拒绝 → 验证降级路径 | 把已有的降级传统扩展成矩阵化测试 |
| H6 | 影子评测 | 新配置与线上并行，对比指标分布再放量 | 平台级发布纪律 |
| H7 | 人工标注台 | 低置信回答入队 → 标注 → 回流 golden set | 形成数据飞轮（规模可小） |
| H8 | 配置版本化 | prompt/检索参数/模型版本 ↔ eval run id 绑定 | 可追溯、可回滚 |

**验收总标准**：任意一次改动（换模型、改 prompt、调检索参数、改 Agent 图）都能一条命令产出"对比报告"，且 CI 能拦住退化。

## 5. LangGraph 编排设计

| 图 | 节点链 | 关键机制 |
| --- | --- | --- |
| **Ingestion Graph** | 解析 → 结构化分块 → 去重/版本比对 → 向量化 → 索引 → 自检 | 断点续跑；大文件分批；失败隔离到单文档（**替代队列框架**） |
| **QA Graph** | 改写(condense/扩展) → 检索 → 相关性判级 → 生成 → 引用校验 → 拒答判定 | conditional edge 做判级；拒答是一等分支 |
| **Agentic Graph** | planner → 工具调用（含 MCP 工具）→ 反思/无进展检测 → 汇总 → HITL 审批 | `interrupt` 做人工审批；checkpoint 支持恢复 |

State 必须包含：`question / rewritten_query / evidence[] / citations[] / verdict / tool_calls[] / cost / trace_id`。
理由：**Harness 的全部指标与轨迹回放都依赖这个 state schema**。

## M1 · 双端同口径最小闭环（约 3 周）[可验 / 对外]

> 这一阶段的价值**不是"又一个后端"**，而是"同一套评测口径下的双端对比"。

- [ ] FastAPI 骨架 + Postgres(pgvector，单库起步) + 本地模型通道（Ollama/vLLM 或复用 ONNX）
      —— **不引 MinIO/Redis**：先用本地磁盘与进程内任务
- [ ] 摄取：上传 → 解析（PDF/DOCX/MD/TXT）→ 结构化分块（移植现有逻辑）→ embedding → 入索引
- [ ] 检索 / 生成 / 引用 / 拒答：与前端同口径（沿用现有默认值与调参结论）
- [ ] **跨语言分块一致性测试**：TS 与 Python 对同一语料产出**相同 contentHash**，不一致 CI 红 ← 亮点
- [ ] **双端对比报告**：同一 golden set 跑出召回一致性 / p50-p95 延迟 / 内存峰值 / 单次成本 / 离线可用性，
      并给出结论「什么场景该用哪端」 ← 亮点
- [ ] Harness v1：Python 评测脚本，指标与门槛与前端一致（recall@k / MRR / 要点 / 拒答 / 冗余）
- [ ] 前端新增「服务器模式」开关，引用卡片/拒答 UI 直连后端

**验收**：一条命令端到端问答带引用；双端对比表产出且结论写进 `docs/`。

## M2 · 可靠性与弱模型工程（约 3 周）[可靠]（替代 v1 的"生产化多租户"）

- [ ] **拒答能力提升**：0.40 → 目标 ≥0.60（零误拒约束下）。手段：精排绝对分/对比度/多信号融合，逐个扫描可用性
- [ ] **口语化查询专项**：当前 s 组 recall@3 = 0.2857（技术措辞 0.92）→ 目标 ≥0.50。
      手段：查询扩展（本地小模型生成 2–3 条术语化改写 + 多查询 RRF）或 HyDE
- [ ] **答案侧拒答裁决**：检索侧只做粗拒，细拒交给答案侧 `verifyAnswer`，并用标注集量化（P/R 进 CI）
- [ ] **自一致性度量**：同题多次采样的答案一致性；低置信时回退/追加检索
- [ ] **增量索引与索引版本**（核心难点：保留机制、砍掉队列框架）：
      内容哈希去重、变更重算、软删除、版本表 + 灰度重建任务
- [ ] **ACL 检索过滤**（唯一保留的"平台"条目）：租户/部门/密级在**召回层**生效，而非后过滤；
      并防"通过结果条数推断无权文档存在"
- [ ] 引用强制闭环：逐句角标 → 越界引用检测 → 证据收敛校验（补齐边界用例）

**验收**：拒答 ≥0.60 且正样本误拒 = 0；口语化 recall@3 ≥0.50；越权查询命中数恒为 0；改文档后索引自动增量重建。

**验收**：CI 能拦住"更准但更贵/更慢"的改动；任一问题可用轨迹回放定位到具体节点。

## 8. 非目标（明确砍掉，写进 README「不做什么」）

| 砍掉的 | 理由 |
| --- | --- |
| 多租户体系 / RBAC 矩阵 / 配额限流 / 审计台 | 纯企业平台运维，挤占 AI 能力开发时间；面试官不会因为你有 RBAC 觉得你懂 AI |

## 9. 面试可讲的重难点（亲手做过才讲）

1. **跨语言分块一致性**：TS 与 Python 对同一语料产出相同 `contentHash`
2. **ACL 在召回层过滤**：后过滤会污染召回，且要防"条数推断无权文档存在"
3. **引用精度 ↔ 拒答率的成对权衡**：拒答越激进误拒越多，必须成对设门槛
4. **弱模型可靠性工程**：0.5B/7B 上做引用强制 + 拒答 + 证据收敛 + 自一致性
5. **轨迹回放**：不改代码、不调模型复现决策路径
6. **Agent 成本控制与无进展检测**：多跳何时停、如何判"再搜也没用"
7. **索引灰度重建**：换分块/换模型时老数据不中断服务
8. **工具调用的间接提示注入防护**：工具返回内容不得篡夺用户意图
9. **资源受限工程**：内存预算、推理锁、模型卸载/重载抖动、单线程 WASM
10. **评测集治理**：难例回流与数据集腐烂
